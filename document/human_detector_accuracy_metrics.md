# HumanDetector 精度評価結果の見方

この文書は、点正解データと `HumanDetector` の保存結果から算出する精度指標の意味をまとめたものである。

## 評価方法

正解データには、対象マネキンの胴体中心付近の点をフレームごとに記録する。
`HumanDetector` が出力した `MATCH` のBBoxがこの点を含む場合、そのフレームでは対象を正しく発見したとみなす。

```text
対象点を含む MATCH BBox がある  → 正しく発見
対象点があるが MATCH BBox がない → 見逃し
対象点を含まない MATCH BBox      → 誤検出
```

この評価は、BBoxの大きさ・形状そのものの正確さではなく、**対象マネキンを検出・識別できたか**を評価する。

## 最終 MATCH の指標

| 指標 | 計算式 | 意味 |
| --- | --- | --- |
| TP（True Positive） | 対象点を含む `MATCH` の数 | 正しく対象マネキンを発見した回数 |
| FN（False Negative） | 対象点があるのに対応する `MATCH` がない数 | 対象マネキンの見逃し回数 |
| FP（False Positive） | 対象点を含まない `MATCH` の数 | 別人物・背景などを対象と誤判定した回数 |
| Precision | `TP / (TP + FP)` | `MATCH` と表示したものがどれだけ正しいか |
| Recall | `TP / (TP + FN)` | 対象マネキンをどれだけ見逃さずに発見できたか |
| F1-score | `2 × Precision × Recall / (Precision + Recall)` | PrecisionとRecallを1つにまとめた値 |

Precisionが低い場合は誤検出が多い。Recallが低い場合は見逃しが多い。両方を同時に改善したい場合にF1-scoreを見る。

`Accuracy` は、対象がいないフレームが多い動画では「何も検出しない」だけで高く見えるため、主指標には使わない。

## 段階別再現率

対象点を含むBBoxが各判定段階に存在したフレームの割合を保存する。

```text
YOLO人物BBox
  ↓ 最小BBox条件を通過
ReID入力
  ↓ OSNet類似度が閾値以上
MAYBE
  ↓ 追跡・確認フレーム数を満たす
MATCH
```

| 指標 | 判定 | 分かること |
| --- | --- | --- |
| YOLO人物BBox再現率 | 対象点を含む人BBoxがある | YOLOが対象の人領域を捉えたか |
| ReID入力再現率 | 対象点を含み、`SKIP`ではないBBoxがある | 最小サイズ条件を通過しOSNetに渡せたか |
| MAYBE以上再現率 | 対象点を含む`MAYBE`または`MATCH`がある | OSNet類似度が閾値を超えたか |
| MATCH再現率 | 対象点を含む`MATCH`がある | 最終的に対象として確定できたか |

この値は、**対象マネキンに対する段階別再現率**である。対象外の全人物に点を付けていないため、YOLO全体のPrecisionや対象外人物の見逃し率を示すものではない。

### 調整箇所の判断例

| 傾向 | 考えられる確認・調整箇所 |
| --- | --- |
| YOLO人物BBox再現率が低い | センサ画質、YOLOモデル、`pred_thres`、最小BBox条件 |
| YOLOは高いがMAYBE以上が低い | 参照画像、服領域クロップ、OSNetモデル、`sim_thresh` |
| MAYBE以上は高いがMATCHが低い | `target_confirm_frames`、`target_confirm_window_frames`、IoU追跡条件 |

## 連続性

ロボットで利用する場合、平均の再現率だけではなく、検出が連続しているかが重要になる。

| 指標 | 意味 |
| --- | --- |
| 最長連続見逃しフレーム数 | 対象が見えているのに正しい`MATCH`が出なかった最大連続フレーム数 |
| 最長連続MATCHフレーム数 | 正しい`MATCH`が続いた最大連続フレーム数 |
| 最初のMATCHまでのフレーム数・秒数 | 対象が最初に評価可能になってから、初めて正しい`MATCH`が出るまでの遅れ |

`ignore`、`no_target` のフレームは連続区間を分け、見逃し・MATCHの連続数には含めない。

## 処理速度

検出結果に保存されている各フレームの `processing_time_s` と `processing_fps` から、以下を算出する。

| 指標 | 意味 |
| --- | --- |
| 平均FPS | 全フレームの平均処理速度 |
| 中央値FPS | 一時的な極端な遅延の影響を受けにくい代表速度 |
| 最小FPS | 最も遅かったフレームの処理速度 |
| 平均処理時間 | 1フレームに要した平均時間 |

この値は実行したPC・モデル・表示処理を含む条件での結果である。Jetsonでの運用性能を判断する場合は、Jetson上で同じ条件で再測定する。

## 今回の結果

対象動画：`2-6-hiroto.mp4`（96フレーム、対象あり96フレーム）

| 指標 | 結果 | 解釈 |
| --- | ---: | --- |
| TP | 60 | 60フレームで対象を正しく`MATCH`できた |
| FP | 0 | 今回の動画では、対象外を`MATCH`した記録はない |
| FN | 36 | 36フレームで対象を`MATCH`できなかった |
| Precision | 1.000 | 出力された`MATCH`はすべて対象を含んでいた |
| Recall | 0.625 | 対象が見える96フレームのうち60フレームで最終確定できた |
| F1-score | 0.769 | Precisionは高いが、Recall改善の余地がある |
| YOLO人物BBox再現率 | 0.729（70 / 96） | 26フレームでは対象点を含む人物BBoxがなかった |
| ReID入力再現率 | 0.729（70 / 96） | 今回はYOLOで捉えた70フレームすべてがReID入力へ進んだ |
| MAYBE以上再現率 | 0.729（70 / 96） | ReID入力まで進んだ70フレームはMAYBE以上だった |
| 最終MATCH再現率 | 0.625（60 / 96） | 10フレームはMAYBEからMATCHへ確定しなかった |
| 最長連続見逃し | 18フレーム | 最大18フレーム連続で最終MATCHがなかった |
| 最長連続MATCH | 22フレーム | 最大22フレーム連続で正しくMATCHできた |
| 最初の正しいMATCH | 12フレーム目、0.10秒 | 確認フレーム数による確定待ちを含む |
| 平均FPS | 62.95 | このPC・現在の実行条件での平均処理速度 |
| 中央値FPS | 47.24 | 通常時に近い処理速度の目安 |
| 最小FPS | 3.41 | 一時的に最も遅かったフレーム |

### 今回の優先的な考察

最終Precisionは1.000であり、今回の動画では誤って対象を`MATCH`していない。一方、Recallは0.625で、主な課題は誤検出の抑制ではなく見逃しの削減である。

最初にYOLO人物BBox再現率が0.729まで低下しているため、36件の最終FNのうち少なくとも26フレーム分は、YOLOの人領域検出以前の段階に原因がある。そのため、まずはセンサ条件、YOLOモデル、`pred_thres`、最小BBox条件を確認する。その後、YOLOで捉えられたが最終MATCHに至らない10フレームについて、追跡・確認フレーム数の条件を確認する。

## 座標系の注意

今回の正解点は元動画の640×480座標で保存されている。一方、HumanDetectorは設定により160×120へリサイズしてからBBoxを出力している。

精度算出プログラムでは、正解点を次の倍率で検出BBox座標へ変換してから照合する。

```text
x: 160 / 640 = 0.25
y: 120 / 480 = 0.25
```

この変換を行わないと、同じ対象を示す点とBBoxでも座標が一致せず、すべて見逃しとして計算される。
